# Demo portfolio

This directory holds a small portfolio generated by Portfolio Manager itself. It exists to show
what the tool produces and to give every command something to work on.

```text
examples/
├── build_demo.py              Regenerates the missing entries (idempotent)
└── portfolio/
    ├── config.json            Points at the portfolio root (".")
    ├── assets/                Source files attached to page bundles
    ├── content/               6 entries, 17 generated _index.md pages
    └── data/portfolio_stats.json
```

## Use it

```bash
# from the repository root
python -m pfm -c examples/portfolio/config.json check
python -m pfm -c examples/portfolio/config.json stats
python -m pfm -c examples/portfolio/config.json list
python -m pfm -c examples/portfolio/config.json serve --open
```

Or with the Makefile: `make demo` / `make serve`.

## What it demonstrates

| Entry | Type | Status | Specific feature |
|---|---|---|---|
| Portfolio Manager | project | published | `repository`, `demo` |
| Homelab sensor node | project | in-progress | work in progress |
| MailGuard threat model | lab | published | `diagram` |
| OSINT collection pipeline | lab | published | `dataset` |
| Civilian populations… | publication | published | page bundle + attached PDF + `source_url` |
| Thinking in Systems | reading | draft | `author`, draft handling in indexes |

`build_demo.py` skips entries that already exist, so it is safe to run after a `git pull`.

The PDF in `assets/` is a minimal one-page document used only as a demonstration attachment.
